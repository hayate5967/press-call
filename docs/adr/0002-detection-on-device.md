# ADR-0002: 静止判定をデバイス側で行う

- 状態：承認
- 日付：2026-11-15

## 背景

Press 合図は、胸の上での静止が設定時間続いた瞬間に出す必要がある。判定を行う場所によって、合図の遅れが大きく変わる。

## 選択肢

| 選択肢 | 良い点 | 気になる点 |
| --- | --- | --- |
| A. デバイス（ESP32）で判定 | 通信を待たずに合図できる。電波が切れても動く | ファームが複雑になる。ロジックの更新に書き込みが必要 |
| B. サーバやスマホで判定 | ロジックを更新しやすい | センサー値を常時送る必要があり、通信の遅れがそのまま合図の遅れになる |

## 決定

A を採用する。判定ロジックは Arduino に依存しない C++（`firmware/lib/detection`）に切り出す。

## 理由

合図の遅れ（目安 50ms 以内）と、電波が途切れても練習できること（NFR-04）を両立できるのはデバイス側だけ。

## 影響

- 判定ロジックは PC 上でテストできる形にし、部室で取った生データをテストの入力にする（NFR-13）。
- しきい値は Web アプリから設定で変えられるようにして、書き込みなしで調整できるようにする。
