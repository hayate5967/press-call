# ADR-0009: 生データの保存方法

- 状態：承認
- 日付：2026-11-15

## 背景

判定ロジックを後から検証するため、センサーの生データ（加速度 3 軸＋角速度 3 軸、100Hz）をセットごとに残したい。1 セット 30 秒で約 1.8 万個の数値になる。

## 選択肢

| 選択肢 | 良い点 | 気になる点 |
| --- | --- | --- |
| 1 サンプル 1 行で DB に保存 | SQL で集計しやすい | 行数が膨大になる |
| JSON で DB に保存 | 読みやすい | 大きい。Workers での解析が CPU 10ms を超える恐れ |
| 16 ビット整数のバイナリを DB の bytea 列に、別テーブルで保存 | 1 セット約 36KB と小さい。API は解析せず保存するだけ | 読むときにデコードが必要 |
| オブジェクトストレージ（Cloudflare R2） | 大容量に強い | 最初から使うには構成が増える |

## 決定

バイナリ（形式版 1：加速度 X・Y・Z、角速度 X・Y・Z の int16 リトルエンディアン）を `set_raw_data` テーブルの bytea 列に保存する。

## 理由

週 20 セットでも年約 37MB で、Neon の無料枠 1GB に十分収まる。別テーブルにすることで、一覧画面で重いデータを読み込まない。

## 影響

- 送信は `PUT /device/sets/{clientSetId}/raw`（`application/octet-stream`、上限 256KB）。
- 容量が足りなくなったら R2 に移す。
