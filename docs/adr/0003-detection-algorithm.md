# ADR-0003: セット・レップ・静止の判定と速度推定のアルゴリズム

- 状態：提案（生データを取ってから決める）
- 日付：2026-11-15

## 背景

MPU-6050 の加速度・角速度から、バーの上下方向の速度を推定し、下降・静止・挙上を判定する必要がある。加速度の積分はドリフト（誤差の蓄積）が起きやすい。

## たたき台

- 状態遷移：上 → 下降 → 静止 → （自動合図モードなら合図）→ 挙上 → 上。実装は `firmware/lib/detection/src/pause_detector.*`。
- 速度：重力成分を除いた上下方向の加速度を積分し、静止を検知するたびに速度を 0 にリセットしてドリフトを抑える（ZUPT）。
- 「静止」：速度の絶対値がしきい値以下（初期値 0.05 m/s）。
- 「動き出し」：速度の絶対値が 0.15 m/s 以上。
- 静止のしきい値は設定で変えられる（FR-D13、`stillThreshold`）が、**動き出しのしきい値（0.15 m/s）未満**に限る（2026-11-17 決定）。静止のしきい値が動き出し以上だと、同じ速さが「止まっている」と「動いている」の両方に当てはまり、胸に着く前の減速や挙上の始まりまで静止とみなしてしまうため。上限は `packages/shared` の `STILL_THRESHOLD_MAX_MPS` として API の入力チェックに使い、ファームも範囲外の値は警告を出して既定値を使う。動き出しのしきい値を変えるときは、この上限も一緒に変える。
- セット終了：一定時間（例：10 秒）動きがない。

## 決め方

1. 部室で数セット分の生データ（`firmware/src/main.cpp` が出す CSV）を取る。
2. 自動合図・回数記録・わざとフライングした場合のデータで、しきい値を調整する。
3. 取ったデータを `firmware/test` のテスト入力にして固定する。

## 影響

しきい値が決まったら、この ADR の状態を「承認」にして値を書き込む。
