# ADR-0006: デバイスのペアリング方式

- 状態：承認
- 日付：2026-11-15

## 背景

部室の ESP32 を自分のアカウントに紐づけ、デバイストークンを発行する必要がある。ESP32 には画面もキーボードもない。

## 選択肢

| 選択肢 | 良い点 | 気になる点 |
| --- | --- | --- |
| A. Web アプリに出たコードを ESP32 の設定ページに入力 | ESP32 がオフラインでも入力できる | 独自方式になる |
| B. ESP32 に出たコードを Web アプリで入力（OAuth Device Authorization Grant、RFC 8628） | 標準規格。GitHub CLI やテレビと同じ方式 | ペアリング中は ESP32 がネットにつながっている必要がある |

## 決定

B（RFC 8628）を採用する。手順は次のとおり（部室で iPhone 1 台で完結する）。

1. 設定モードの ESP32 の AP に iPhone をつなぎ、テザリングの SSID とパスワードを登録する。
2. テザリングをオンにする。ESP32 がつながり、`POST /device/authorize` でコードを受け取る。
3. iPhone で `http://bench.local`（mDNS）を開き、コードと許可用リンクを表示する。
4. リンク（`verificationUriComplete`）から Web アプリを開き、許可する。
5. ESP32 は `POST /device/token` のポーリングでデバイストークンを受け取る。

## 理由

標準規格に沿うことで、エラー（`authorization_pending`、`slow_down` など）や期限（10 分）の扱いを自分で考えずに済み、説明もしやすい。

## 影響

- スマホは iPhone を前提とする（Android は機種によって `.local` を解決できない）。
- RFC はフォーム形式・snake_case だが、ESP32 の実装を単純にするため JSON・camelCase で受ける。流れとエラー名は RFC に合わせる。
- デバイストークンは JWT にせず、DB で毎回確認する不透明トークンにする（盗難時にすぐ失効できるように）。
