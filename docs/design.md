# 画面デザインの決まり

Web アプリ（`apps/web`）の見た目の決まり。Apple の [Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines)（HIG）を参考に、iPhone で片手で使いやすいことを優先する。色の値は `apps/web/src/style.css` が正。

## 色の役割

| 役割 | 割合の目安 | 変数 | 使うところ |
| --- | --- | --- | --- |
| ベース | 約 70% | `--background`（淡い水色）・`--card`（白） | 画面の地、内容をまとめるカード |
| メイン | 約 25% | `--primary`（青） | 押せるもの（ボタン・リンク・選択中のタブ）、グラフの棒 |
| アクセント | 約 5% | `--highlight`（オレンジ） | 新しく届いたセットなど、いちばん目を引きたい 1 か所だけ |
| 意味の色 | 必要なときだけ | `--success`・`--warning`・`--destructive` | 成功・注意・エラーや削除。ほかの用途には使わない |

- グラフの色は `--chart-rep`（通常のレップ、青）と `--chart-premature`（合図より前に挙げたレップ、黄土色）。色覚の違いを模した比較でも十分に離れていること（OKLab の差 27 以上）と、明るさ・彩度・背景とのコントラストを検証スクリプトで確かめた。ダークでは本文の色より少し暗くしている
- 同じ色に別の意味を持たせない（HIG）。青は「押せる」、オレンジは「新しい・注目」に固定する
- 色だけで意味を伝えない。アイコン・文字・形でも同じことが分かるようにする（グラフの premature のレップも、色に加えて印や凡例を付ける）
- ライト・ダーク・「コントラストを上げる」の 3 つで色を用意する。ダークでは影の代わりに、カードを地より明るくして浮かせる

## コントラスト

文字と背景のコントラスト比は 4.5:1 以上（HIG の最低ライン）、本文は 7:1 以上を目指す。今の値（ライト／ダーク）：

| 組み合わせ | ライト | ダーク |
| --- | --- | --- |
| 本文 / 地 | 16.1 | 18.1 |
| 補足の文字 / カード | 6.8 | 7.6 |
| ボタンの文字 / 青 | 5.4 | 7.2 |
| 青の文字 / カード | 5.4 | 6.6 |
| 成功・注意・エラーの文字 / カード | 5.0〜5.2 | 6.0〜9.9 |

色を変えたら、この表の組み合わせを計算し直す。

## 形と大きさ

- 押せるものは高さ 44px 以上（HIG）。ボタンは 44px、大きいボタンは 52px
- ボタンはカプセル形。1 画面で目立つボタン（`default`）は 1〜2 個までにし、ほかは `secondary`（青をうすく敷く）や `ghost` にする
- 文字は iOS の標準に合わせる：画面の見出し 34px 太字、本文 17px、補足 15px、注記 12px。細い字（Light 以下）は使わない
- 入力欄は 17px（16px 未満だと iPhone の Safari が拡大してしまう）
- 画面の左右の余白は 16px。iPhone のノッチやホームバー（セーフエリア）に内容を重ねない

## 画面の組み立て

- 画面の切り替えは下部のタブ（今日・履歴・設定）。タブバーは内容の上に浮かぶすりガラスにし、片手の親指が届く下端に置く。「透明度を下げる」がオンなら不透明にする
- よく押すボタンは画面の下のほうに置く（ログインボタンなど）
- 内容はカードでまとめる。カードは枠線を引かず、地との色の差とやわらかい影で区切る
- 中身がまだない画面は空にせず、なぜ空なのか・どうすればよいかを出す（`EmptyState`）
